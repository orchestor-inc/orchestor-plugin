# エビデンスからアクションにつなげる AEO ワークフローを実行する

各ワークフローはユーザーの目標とワークスペースの範囲内に限定してください。デフォルトの分析では既存のエビデンスを使用します。新規の収集、レコード作成、コンテンツ公開、および外部への働きかけ（outreach）は個別のアクションであり、対応するリクエストが必要です。

## ワークフローの選択

| 目標 | 参照 | 完了エビデンス |
| --- | --- | --- |
| 信頼できる最初のベースラインを確立する | [ベースライン](references/baseline.ja.md) | 定義されたスコープ、利用可能な観測データ、エビデンスに基づく優先順位 |
| 1 か月またはレポート対象期間をレビューする | [月次監査](references/monthly-audit.ja.md) | 比較可能な期間テーブル、ソースエビデンス、制限事項 |
| 代わりに引用されている競合他社を調査する | [引用の不足](references/citation-gap.ja.md) | プロンプト / ソースのギャップとエビデンスに基づく次のアクション |
| コンテンツの一部を改善して評価する | [コンテンツサイクル](references/content-cycle.ja.md) | 提案された変更、承認境界、およびフォローアップ設計 |
| クライアントまたは社内チーム向けにレポートを調整する | [対象読者](references/audience.ja.md) | 受信者の意思決定のために提示される同一のエビデンス |

## リソース操作の構成

アイデンティティには `orchestor-brands`、質問セットには `orchestor-prompts`、要求された収集には `orchestor-runs`、集計には `orchestor-reports`、保存された回答のエビデンスには `orchestor-answers`、ソースレコードには `orchestor-sources` を使用します。必要なスキルのみを読み込んでください。公開ページには `orchestor-research` を使用し、要求されたアクションレコードには `orchestor-manage-issues` を使用します。

[構成例](references/composition.ja.md) に入力と出力が示されています。リソーススキルは正確な CLI コントラクトを保持します。この親スキルは、重複するコマンド実装ではなく、タスクの順序と結果を管理します。不足している兄弟スキルは、現在の公開 CLI ヘルプまたはドキュメントを通じて解決できます。

## 共通の事前確認

接続、ワークスペース、ブランド / 競合他社、既存のプロンプト、期間、および要求された出力を確認します。現在の CLI ヘルプまたは MCP スキーマを使用してください。社内限定スキル、未公開のオペレーターコマンド、またはプライベートリポジトリのパスを、顧客ワークフローの必須ステップとして使用しないでください。

## エビデンスからアクションへのループ

1. **観察:** 既存のエビデンスとそのカバレッジを精査します。
2. **理解:** 同一コホートを比較し、回答 / ソースを精査します。
3. **優先順位付け:** 明示的なエビデンスと不確実性を伴う少数のアクションを特定します。
4. **要求時に実行:** ユーザーの要求したスコープおよび利用可能な製品機能の範囲内でのみ、タスクを作成し、コンテンツを編集し、または限定された収集を開始します。
5. **要求時に再観察:** 比較可能なコホートを使用し、エビデンスでは確立できない因果関係を主張することなく差異を報告します。

## 返却内容

意思決定にそのまま使える簡潔なレポート: スコープ、観測データ、エビデンスのリンク / ID、推奨アクション、および次のチェックポイント。欠落しているカバレッジと未完了の操作を明記します。代理店の場合は、クライアントごとにスコープとデータを必ず分けて管理してください。

インストールされている場合、`orchestor-aeo-best-practices` はより詳細なレビュー規則を提供します。ここにあるリファレンスだけで、兄弟スキルがなくてもワークフローを実行するのに十分です。
