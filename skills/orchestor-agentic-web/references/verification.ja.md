# エビデンス主導のチェック

修正を提案する前に、失敗した具体的なチェックとそのエビデンスを確認してください。ファイルの欠落、リクエストの失敗、アクセス不能なレンダリング、サポートされていないチェックには、それぞれ異なる原因があります。単一の失敗がサイト全体を説明していると決めつけないでください。

**誤り:** robots ファイルの変更によってブランドの可視性が向上すると主張したり、1 つのチェックに合格したからといって監査全体が修正されたと見なしたりすること。

**正しい対応:** 影響を受けたチェックを再実行し、変更前／変更後のエビデンスを保持します。技術的な変更によって何が可能になるかを説明し、どのような広範な影響が未測定のままであるかを明記してください。

チェックフィードバックは不同意やコンテキストを記録するものであり、それ自体が検証の成功を意味するものではありません。ユーザーから記録を求められた場合にのみフィードバックを作成してください。Attestation/JWKS エンドポイントは検証用の資料を公開します。署名検証が実行されていない限り、取得したアテステーションを暗号学的に検証済みであると説明しないでください。
