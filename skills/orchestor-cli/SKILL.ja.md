# Orchestor CLI の操作

確実なコマンド実行のためにこのスキルを使用します。本スキルは自己完結型です。タスク固有の分析は関連する製品スキルで行います。

## 適用する場面

- ユーザーが Orchestor への接続、ワークスペースの選択、または認証の確認を求めた場合。
- 再現可能な CLI コマンドの記述や、そのレスポンスの診断が必要な場合。
- タスクに出力フィルタリング、ページネーション、冪等性、または非同期実行が含まれる場合。

## クイックスタート

```bash
orc --version
orc status
orc auth status
orc workspace current
```

`orc` が見つからない場合は、[CLI ガイド](https://orchestor.io/docs/cli) に従ってください。
不慣れなフラグを使用する前に、リーフコマンドの `--help` を確認してください。親名前空間のみを出力して正常終了したヘルプは、リーフコマンドが利用可能であることを証明するものではありません。
フォールバックとして REST パスを捏造したり、内部コマンドを試行したりしないでください。

## 優先度別の実行ルール

| 優先度 | ルール | 参照 |
| --- | --- | --- |
| Critical | ワークスペースと接続を検証し、出力に認証情報を含めない | [認証](references/authentication.ja.md) |
| Critical | 読み取り、プレビュー、書き込み、および有料収集を分離する | [安全な変更](references/safe-changes.ja.md) |
| High | リクエストを制限し、継続状態を保持する | [出力とページネーション](references/output-pagination.ja.md) |
| High | 再試行する前に失敗を分類する | [エラーリカバリ](references/error-recovery.ja.md) |

## 手順

1. 正確なユーザータスクと対象のワークスペースを解決します。既知のワークスペース ID を再利用します。
   特に複数クライアントの作業では、データ呼び出しに `--workspace WORKSPACE_ID` を使用します。
2. 関連するヘルプと既存の状態を読み取ります。必要なフィールドとページ
   サイズのみを選択します。エンドポイントから返された単位とタイムスタンプを保持します。
3. 書き込みの場合は、正確なリクエストを UTF-8 の JSON ファイルに準備し、`--stdin` を使用します。
   サポートされている場合は、送信前に `--dry-run` を使用して形状を検査します。
4. 要求された操作のみを送信します。サポートされている再試行の場合は、同一の
   冪等性キーとまったく同じ本文を維持します。新しい論理操作には新しいキーが必要です。
5. 影響を受けた ID を再読み取りします。非同期処理の場合は、新しいジョブではなく、返されたジョブをポーリングします。
6. 結果、スコープ、根拠 ID、および未解決のエラーを返します。dry run は
   リクエストの準備のみを証明するものであり、受け入れられたジョブは完了した結果ではありません。

## アカウントと自動化

要求された使用量の数値には `orc usage get --help` および `orc costs get --help` を使用します。
コストの調査をプランや支払いの変更へと発展させないでください。API キーまたは
サービスアカウントについては、アクセスリファレンスとコマンドヘルプを確認してください。認証情報の作成または失効は
要求された場合にのみ行います。新しく返されたシークレットをチャットに出力してはなりません。

操作を探すには [コマンドファミリー](references/commands.ja.md) を使用します。これは
カタログスナップショットであり、インストールされているすべてのバージョンで公開されていることを保証するものではありません。
