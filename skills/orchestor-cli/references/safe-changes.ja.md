# 安全な変更と再試行

**誤り:** すべてのコマンドに `--yes` を追加する、タイムアウト後に作成コマンドを
再度呼び出す、またはドライランの成功が書き込みが行われたことを意味すると想定する。

**正しい方法:** 既存の状態を読み取り、要求されたフィールドを準備し、有用な場合は
リクエストをプレビューし、1 回送信した後に、返された ID を読み戻す。

```bash
orc issues create --help
orc issues create --workspace WORKSPACE_ID --stdin --dry-run --format json < issue.json
```

この例はリクエストのプレビューのみを行います。ワークスペースとボディが承認されたタスクと
一致した後に、`--dry-run` を除外して送信してください。更新時に省略されたフィールドは通常、
値が保持されます。明示的な null や配列は、それらをクリアまたは置換する場合があります。
変更をマージする前に、特定のフィールドコントラクトを確認してください。

冪等性がサポートされている場合は、新しい操作に対して 1 つの一意なキーを使用し、
同一のメソッド、パス、クエリ、およびまったく同じボディに対してのみ再利用してください。キーには有効期限が切れる可能性があるため、
有効期間については現在のヘルプを確認してください。異なるコンテンツによって引き起こされた競合を、
新しいキーを暗黙的に選択して操作を重複させることによって解決してはなりません。

測定、バッチ、接続の作成、公開フラグ、メンバーシップの変更、および資格情報の操作には、
それぞれ明確に異なる影響があります。調査またはレポートの要求は、これらの変更を承認するものではありません。
1 回限りのリクエストに定期的な収集を追加しないでください。作成結果が不確かな場合は、再試行する前に返された状態を確認してください。
