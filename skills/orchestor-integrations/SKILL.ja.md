# エージェントと外部サービスの接続

設定済みのサーバーやインストール済みのプラグインは、認証された接続ではありません。
各レイヤーを個別に検証してください。

## 接続の選択

| ニーズ | リファレンス |
| --- | --- |
| エージェントクライアント → ホスト型 Orchestor MCP | [MCP クライアント](references/mcp-clients.ja.md) |
| ワークスペース → アナリティクス、検索、広告、またはインフラプロバイダー | [プロバイダー接続](references/provider-connections.ja.md) |
| プログラムによるアイデンティティまたは再利用可能な CLI アクセス | [自動化アクセス](references/automation-access.ja.md) |
| 公開ブラウザコンテキスト／セッションリソースの調査 | [ブラウザコンテキスト](references/browser-context.ja.md) |

## MCP クイックスタート

クライアントの現在の公式リモート HTTP 設定を使用してください。ホスト型エンドポイント:

```json
{
  "mcpServers": {
    "orchestor": {
      "type": "http",
      "url": "https://mcp.orchestor.io/mcp"
    }
  }
}
```

これは MCP サーバーマップの形状であり、すべてのクライアントに対応する汎用設定ファイルではありません。
ファイルと構文を選択する前に、[エージェントセットアップガイド](https://orchestor.io/docs/agent-setup) と
クライアントのドキュメントをお読みください。

## 手順

1. クライアント／プロバイダー、設定スコープ、および対象のワークスペースを特定します。
2. 既存の接続状態を確認し、要求されたエントリのみを追加します。
3. ユーザーに OAuth を完了してもらいます。チャットでトークンを要求したり、シークレットファイルを検査したりしないでください。
4. 再接続し、実際に利用可能なツールまたはプロバイダーリソースを調査します。
5. タスクにアクセスの検証が含まれている場合は、小規模な承認済み読み取りを実行します。
6. 設定、認証、選択されたワークスペース、および読み取り結果を個別の事実として
   返します。完全な成功を主張せずに、未解決のステップを報告してください。

## 境界

読み取り専用のプロバイダー接続は、管理アクセスとは異なります。無関係な読み取りエラーを
解決するために、より広範なスコープを要求したり、プロバイダープロパティを作成したりしないでください。
最新のドキュメントがない限り、セルフホスト、Docker、代替トランスポート、またはクライアント固有の
機能のサポートを約束しないでください。

製品の接続サーフェスについては、[コマンドファミリー](references/commands.ja.md) を参照してください。
