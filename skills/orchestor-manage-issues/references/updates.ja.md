# 更新、リレーション、およびリトライ

更新する前に、対象のワークスペースとプロジェクトを検索してください。利用可能な場合は、`issues get` に既知の内部 ID を使用してください。一覧表示では結果フィールドを絞り込み、選択されたレコードの description は必要な場合にのみ取得してください。

**誤り:** あいまいなネットワーク障害の後に新しい idempotency key で作成を再試行したり、既存のラベルを読み取らずに 1 つのラベルを追加するために labels 配列を置換したりすること。

**正しい対応:** 元のリクエスト／キーを保持し、結果を調査してください。同一の操作および本文に対してのみ、同じキーを再利用してください。更新を行う際は、無関係な値やリレーションシップを保持してください。規約でそのように定められている場合、labels 配列は置換となります。送信前に意図したマージ済みのセットを計算してください。

リレーション、コメント、リアクション、購読、およびお気に入りは、それぞれ別個の書き込みです。ユーザーが要求した記録操作のみを実行してください。関連する状態を読み戻して確認してください。親 Issue が存在するというだけで、リレーションが関連付けられたと主張しないでください。
