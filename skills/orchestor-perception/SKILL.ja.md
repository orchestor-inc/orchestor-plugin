# 付与されたブランド特性の分析

付与された各特性を、保存された正確なテキストに根拠付けます。ソースの証拠をもっともらしい要約で置き換えないでください。

## 適用基準

「AI の回答は当社に何を関連付けているか？」、「認識されている強みを比較する」、「この属性の背景にある引用を表示する」、または明示的な観測結果のインポートリクエストに使用します。通常の言及シェアには、利用可能であれば `orchestor-reports` 、 `orchestor-answers` 、および `orchestor-sources` を使用してください。

## 優先度ルール

| 優先度 | ルール | 参照 |
| --- | --- | --- |
| Critical | 正確なソーステキスト、ダイジェスト、および UTF-16 オフセットを保持する | [引用された証拠](references/quoted-evidence.ja.md) |
| Critical | リクエストされた有効な観測結果のみをインポートする | [インポートのセマンティクス](references/import.ja.md) |
| High | 属性、センチメント、および事実の主張を区別して維持する | [解釈](references/interpretation.ja.md) |

## クイックスタート

```bash
orc perception text list --help
orc perception text list --workspace WORKSPACE_ID --brand-id BRAND_ID --limit 20 --format json
orc reports perception get --help
```

境界付きの証拠ページを読み取ります。空のページであっても next_cursor が含まれている場合があるため、タスクでさらに証拠が必要な場合は同じフィルターと制限を引き続き使用してください。

## 手順

1. ブランド、プロンプト/トピック、プラットフォーム、および期間のスコープを確定します。
2. 関連するレポートと保存されたそのテキスト証拠を読み取ります。
3. 回答 ID 、ダイジェスト、セグメントの同一性、オフセット、および正確な引用を記録します。
4. 回答がブランドに帰属させている内容と、自身の解釈を分離します。
5. インポートがリクエストされた場合は、現在のヘルプとスキーマに照らして本文を検証し、安定したべき等性キーを保持した上で、それらの観測結果のみを送信します。
6. 生成されたレポートまたはインポートレシートを読み戻し、不足しているカバレッジを明記します。

## 戻り値

引用された証拠、回答 ID 、スコープ、および制限を含む属性の比較。インポートの場合は、レシートと影響を受けるブランドを含めます。元の回答が書き換えられた、またはすべてのブランドのアノテーションが置換されたと示唆しないでください。

[コマンドファミリ](references/commands.ja.md) を参照してください。
