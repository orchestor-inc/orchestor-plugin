# Web サイトからのレビュー済みオンボーディング

`observations create` はワークスペース用の編集可能なオンボーディングリソースを生成できます。
代理店の場合、website は代理店自身のものではなく、クライアントのブランド Web サイトを意味します。

**誤り:** ユーザーが brand facts の確認のみを求めたのに自動的に one-shot を渡すことや、生成された競合の提案をレビューなしですべて送信すること。

**正しい対応:** 要求された最小限のフローを選択します。`profile_only` は、トピック、プロンプト、または測定を生成することなく編集可能な brand facts を公開し、one_shot をオーバーライドします。通常のレビューフローでは、確定ステップの前にユーザーが構成をレビューできます。one-shot は、初期測定の開始が要求された場合にのみ使用してください。

`observations configurations confirm` の前に、生成された構成を確認してください。
返されたモニタリングスコープと ID を使用してください。現在の確定コントラクトには、レビュー済みの brand、competitors、topics、prompts、および dimensions が必要です。無料プランでは 1–5 個、有料プランでは 10–40 個の選択されたプロンプトが必要であり、選択された親トピックと最大 40 個の送信候補（candidates）が含まれている必要があります。任意のプレースホルダー ID を生成するのではなく、送信前に実際のスキーマを検証してください。

送信されたすべての競合は、その `selected` フラグに関係なく含まれます。不要な競合は送信配列から除外してください。確定（confirmation）は一般的な部分パッチではありません。レビュー済みのユーザー編集を保持し、必要な完全な形状（full shape）を提供してください。
