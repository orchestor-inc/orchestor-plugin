# Orchestor ワークスペースの整理

ワークスペースをアクセス境界として使用し、その内部の整理にプロジェクト/イニシアチブを使用します。クライアント間の分離をシミュレートするためにプロジェクトを使用しないでください。

## 適用するタイミング

「ワークスペース/プロジェクトの作成」、「このマイルストーンの検索」、「このドキュメントの添付」、「このビューの保存」、または明示的なメンバーシップ/アクセスの変更に使用します。イシューの作成と更新には、インストールされている場合、 `orchestor-manage-issues` を使用してください。

## リファレンスの選択

- アクセスまたはワークスペースの変更前には [スコープとメンバーシップ](references/scope-access.ja.md) 。
- 作業の整理には [プロジェクトとイニシアチブ](references/projects-initiatives.ja.md) 。
- アーティファクトと保存されたフィルタには [ファイルとビュー](references/files-views.ja.md) 。

## クイックスタート

```bash
orc workspaces list --help
orc projects list --workspace WORKSPACE_ID --fields id,projectKey,name --format json
orc initiatives list --workspace WORKSPACE_ID --limit 20 --format json
```

## 手順

1. ユーザーまたはその製品 URL から提供されたワークスペースと ID を再利用します。
2. 現在の状態を読み取り、必要な範囲でのみ名前を解決します。 URL は workspace 、 project_id 、および milestone_id を提供できます。それらのアイデンティティを保持してください。
3. 読み取りリクエストを、作成/更新、メンバーシップの変更、アーカイブ、一時停止/再開、または公開と区別します。要求されたアクションのみを実行してください。
4. 無関係なフィールドとリレーションシップを保持します。最小限の更新を優先してください。
5. 影響を受けたレコードを読み戻し、その ID と状態を報告します。

## 返却内容

ワークスペース、変更または特定されたリソース、関連するメンバーシップ/リレーションシップの状態、およびエビデンス ID 。タスクの範囲を超えてメンバーの詳細やファイルの内容を開示しないでください。アクセスが拒否された場合は、内部の管理者用ツールを探すのではなく、必要な製品権限を提示してください。

[コマンドファミリー](references/commands.ja.md) を参照してください。
