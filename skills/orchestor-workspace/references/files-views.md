# Files and saved views

A file registration response is not proof that bytes have been uploaded. Read the
current upload/content contract, including purpose, filename, MIME type, expected
byte size, and any returned upload step. Read back the file or content receipt.

**Incorrect:** report a document as attached after creating only its metadata,
or store a customer export under a publicly distributed skill directory.

**Correct:** use the intended workspace and explicit purpose/owner reference,
complete the supported transfer, then verify the resulting ID and attachment.
Issue attachments use an issue owner reference when required by the contract.
Never log signed upload URLs or expose private content to debug a failed transfer.

Saved views capture requested filters/organization. They are not measurement
schedules or evidence snapshots. Preserve existing defaults unless changing the
default view was explicitly requested.
