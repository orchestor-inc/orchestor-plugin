# Orchestor ワークフローの選択

ユーザーが求める成果から始めます。以下の最小限のワークフローを選択し、関連するスキルがインストールされている場合はロードしてください。兄弟スキルは任意です。スキルが利用できない場合は、リンクされているプロダクトドキュメントを使用してください。

## ワークフローを選択する前に

1. ユーザーが証拠を読みたいのか、設定を変更したいのか、それとも新しい観測を収集したいのかを特定します。レポートを閲覧しても、新たな実行は承認されません。
2. ワークスペース、ブランドまたは Web サイト、比較スコープ、および期間を特定します。既知の ID を再利用してください。解決できない識別子または決定事項についてのみ質問してください。
3. CLI 作業の場合は `orc status` を、MCP 作業の場合はクライアントが公開している MCP ツールを確認します。これらは個別に認証された接続です。このスキルがインストールされているという事実からアクセス権を推測しないでください。

## 何を行おうとしていますか？

| ユーザーの目標 | スキル | 判断のための質問 |
| --- | --- | --- |
| 接続、ワークスペースの選択、CLI 呼び出しのスクリプト化、またはエラーの診断 | `orchestor-cli` | これは分析ではなく、接続またはコマンドの実行ですか？ |
| ブランド、競合他社、または追跡対象ドメインの特定 | `orchestor-brands` | タスクはどのアイデンティティを参照していますか？ |
| プロンプト、トピック、タグ、またはペルソナの設定 | `orchestor-prompts` | 何を測定すべきですか？ |
| 観測の実行または測定状態の確認 | `orchestor-runs` | 収集が要求されましたか？また、その状態はどうなっていますか？ |
| 集計メトリクスの読み取り | `orchestor-reports` | どのスコープとコホートが比較可能ですか？ |
| 保存された回答テキストの確認 | `orchestor-answers` | 主張を裏付ける回答はどれですか？ |
| ソース URL、ドメイン、または引用ギャップの確認 | `orchestor-sources` | 調査が必要なソースレコードはどれですか？ |
| Web サイト、キーワード、市場、企業、または公開ソースの調査 | `orchestor-research` | 証拠は保存された AI 回答の外部にありますか？ |
| エージェントが Web サイトを読み取りナビゲートできるかの確認 | `orchestor-agentic-web` | これはブランドの visibility ではなく、技術的なサイトチェックまたはジャーニーですか？ |
| ブランドに帰属する属性の分析 | `orchestor-perception` | 正確に引用された証拠と属性の比較が必要ですか？ |
| 製品、ショッピングでの露出、需要、またはマーチャントの分析 | `orchestor-shopping` | 対象はブランドレベルの言及ではなく製品ですか？ |
| ワークスペースのメンバーシップ、プロジェクト、ファイル、または保存されたビューの管理 | `orchestor-workspace` | これはワークスペース内の整理およびアクセスに関するものですか？ |
| Orchestor Issue の作成、更新、または割り当て | `orchestor-manage-issues` | 永続的なタスクレコードが明示的に要求されていますか？ |
| MCP またはプロバイダーの接続、あるいはサービスアクセスの設定 | `orchestor-integrations` | 接続の追加または確認を行っていますか？ |
| AEO 分析の妥当性のレビュー | `orchestor-aeo-best-practices` | 比較の品質、証拠、または帰属が問題になっていますか？ |
| ベースライン、月次監査、引用ギャップレビュー、またはコンテンツサイクルの実行 | `orchestor-aeo-workflows` | 目標は上記の複数のワークフローにまたがっていますか？ |

## 成果に必要なもののみを構成する

「なぜ visibility が低下したのか？」については、保存されたレポートと回答から始めます。調査対象のソースを特定した後にのみ公開調査を使用してください。モニタリングの変更は個別に提案してください。無断で測定を実行したり、コンテンツを公開したり、ソースに連絡したりしないでください。

「ブランドのセットアップ」については、レビュー済みのオンボーディングフローを優先します。ブランドに関する事実情報、競合他社、プロンプト、実行チャネル、およびロケールは、測定前に確認する必要があります。ブランドが設定されていることは、観測が存在することの証明にはなりません。

「これをもとにタスクを作成して」については、Issue ワークフローを使用して、作成された ID を返します。タスクレコードの作成要求を、実装やデプロイにまで拡大しないでください。

## 返却内容

選択されたワークフロー、スコープ、結果、証拠、および次の判断事項を記述してください。観測、解釈、提案は分けて記載してください。ユーザーの言語を使用し、コマンド名、メトリクス名、識別子名は正確に維持してください。
