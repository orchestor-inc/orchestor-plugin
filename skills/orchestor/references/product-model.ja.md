# プロダクトの関係性

ワークスペースは認可およびデータの境界です。プロジェクトはその内部で作業を整理するものであり、顧客間におけるワークスペースの分離の代わりとなるものではありません。

ブランドは組織とその比較セットを識別します。トピックとタグはプロンプトを整理します。run は、対象となるコンシューマーチャネル上で保存されたプロンプトの観測を要求します。回答は結果として得られた証拠を保持します。レポートは、定義されたスコープ、日付範囲、およびフィルターセットのもとでその証拠を集計します。

ソースは引用されたドメインやページを記述します。引用はブランドへの言及とは異なり、検索結果は採用された引用とは異なります。Perception はブランドに帰属する特徴を記録しますが、帰属する特徴が必ずしも肯定的なセンチメントであるとは限りません。Shopping レポートは製品の露出やマーチャントに関するものであり、売上の証明ではありません。

Issue、プロジェクト、マイルストーン、イニシアチブ、ファイル、およびビューは、後続の作業を整理します。外部プロバイダーの接続や MCP/CLI 認証は、証拠そのものとは別個のものです。プロバイダーが接続されていることは、データが到着したことの証明にはなりません。

内部デプロイ、データベースの保守、オペレーターによるブラウザ制御、および会社の認証情報は、これらのパブリックなプロダクトスキルの対象外です。公開コマンドが利用できない場合に、プライベートなオペレーターツールを探さないでください。実際の機能または権限の不足を報告し、プロダクトドキュメントを使用してください。
